# Human Layer v7 使用说明

本版沿用同一餐厅、16 位人物和现有 Blender 骨骼动画。五个页面共用场景；顾客继续由已有餐饮规则自主活动。

## 视野大小与观察方向

「进入角色 / 专家」现在占满平台可用屏幕，右侧保留采集、视野、服务动作、设备和标记。默认第一人称视野为水平 90°、垂直 60°。这些是可修改的仿真参数，不是对真实人体视野的测量。

水平范围可以设置为 30–150°，垂直范围为 20–120°。二者独立，按角色保存在当前浏览器。配置服务员后点「新建示范」，采集窗口会预选该服务员并显示其实际 H × V；切换服务员会显示新角色的配置。

相机用真实透视投影和保持比例的有效图像矩形。窗口改变只影响矩形的显示尺寸，不改变水平或垂直角宽；余下部分为视野外遮罩。转头只改变视野中心方向，方向调节在折叠区内。地图、拾取、关键点投影、JPEG 和回放采用相同有效区域。详细坐标协议见 [相机说明](camera-view.md)。

右上角小地图表示餐厅真实地板、家具与所有在场人物位置，轨迹来自控制角色实际走过的坐标。地图作为操作辅助，不属于第一人称视觉传感图像。

## 明确选择团队

在总览点击「框选组队」，场景暂停。拖动选择可见顾客，Shift 可增选或移除；也可在窗口里按 ID 从名单选择。填写组名，设置成员关系和用餐场合，至少两名顾客才能保存。工作人员不加入顾客团队。

团队标签跟随实际位置显示，不更改个体 ID、人格、座位、动作或导航路线。可以编辑成员和属性、解散、导出 JSON；已经属于别组的人不会被自动转移。当前规则没有自动实现团队订桌、共享订单或集体到店，后续决策算法可读取每个人的 `context.group`。详见 [团队接口](customer-groups.md)。

## 点评语言结果

人格库默认打开「点评语言结果」。此处查看离线计算结果和来源，不在浏览器执行词典分析。导入工具保留在高级区域，已有用户档案和人物分配保持可用。

本机已有 54 条 Trip.com／携程返回的餐厅评论正文，以及 10 条此前 notebook 记录（3 条截断片段、7 条无正文）。来源平台、本地文本哈希和文本完整性分别标注；不将携程数据称为大众点评，也不将片段当作完整正文。

经用户确认学术用途，54 条正文已完成 **SCLIWC2024 词级精确匹配分析**。使用作者原生 2024 词典（19,952 词条、116 类别），经 OpenCC 繁转简及 jieba 分词得到 1,252 个有效词，精确命中 1,035 词，覆盖率 82.67%。页面展示总体统计、逐条词类计数、占有效词比例及原文追溯；7 条无正文、3 条片段仍不计算。

匹配口径是原生词典的词级精确匹配；484 个含星号词项未按未经核验的通配规则展开。这是可复算的独立计数方法，不等同官方 LIWC22 或 TextMind 桌面全套输出，也不生成未校准的心理分数。词典只保存在本机独立目录，不进入平台或交付包。具体方法、版本、哈希与边界见 [人格资料库说明](persona-library.md)。

## 采集、回放和接口

每次新建示范先明确文件目录，再生成独立 episode。元数据保存开始时的角色视野配置、人格分配、显式团队和事件配置；帧持续保存实际相机 H/V、有效图像区域、角色坐标、动作及自主状态。改动视野另有事件记录。

回放读取当时保存的团队与相机参数；临时观察不会覆盖当前配置，退出后恢复当前团队。采集和回放期间禁止编辑团队。旧会话缺少团队信息时明确显示历史缺失，不用当前团队替代。未连接实体设备时，signals 为空。

`window.mindspaceHumanLayer.getState()` 返回当前场景、库配置、团队和视野状态；`getGroup(actorId)` 返回独立的团队副本或 null；`getPersona(actorId)` 返回绑定档案。`setBehaviorAdapter(fn)` 接入后续决策方法，仍经过当前角色、座位、路径及控制权约束。设备协议见 [采集接口](capture-api.md)。
