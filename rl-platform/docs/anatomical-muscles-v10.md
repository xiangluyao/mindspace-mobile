# v10 解剖肌肉工作区

动作库的「解剖肌肉」模式显示 Z-Anatomy / BodyParts3D 的标准解剖网格，取代旧的椭球肌肉示意。当前资产为 509 个源表面结构：462 个肌肉表面对象及 47 个相关结缔结构（10 个肌腱、7 个腱膜、30 个支持结构），不能解释为 509 块不同的人体肌肉。另有 206 块源骨整理的参考骨架及 705 个源附着表面。

解剖标准体经过 Blender 整理，脚底归零，身高规范为 1.75 米，Three.js +Y 向上、+Z 向前。它不是依据顾客外观扫描出来的个人肌肉。每个人物可绑定自己的独立配置，但共用该标准解剖来源。肌肉模式会暂停并禁用当前人物的动画播放与进度，退出后恢复原人物预览；未给现有 53 骨人物套用未经校准的肌肉蒙皮。

## 使用

- 在目录搜索名称、英文或源编号，按区域和左右筛选，也可以直接点击可见的肌肉网格。
- 所选肌肉高亮。独显、聚焦、透明度和重置视图只改变观察方式。
- 「移动肌肉」「缩放肌肉」控制实际网格中心的坐标轴。也可输入 XYZ 局部位置（每轴 ±0.15 米）和 XYZ 尺度（每轴 0.5–1.5 倍）。
- 肌腹厚度为 0.6–1.8 倍的几何控制：按源网格主轴计算径向厚度，中部变化较大，两端变化降至零。它不会生成肌肉激活、肌力、应力或生理测量值。
- 撤销、重做、恢复所选或恢复该人物全部肌肉均先修改预览草稿。点击「保存当前人物肌肉配置」后写入浏览器；不同人物和场景互相独立。JSON 导出包含已保存配置及明确标出的未保存草稿。
- 肌肉页只提供肌肉网格编辑器。原有实体、骨骼和关键点模式继续使用原姿态编辑器。

源附着参考列出原始起止标记、相关骨名、源编号和资料中的问题。只有稳定关联的结构才显示对应表面；缺失资料保留未知。蓝绿色表示源起点，橙色表示源止点，紫色表示源类型未指定。附着表面保留源位置，不会随着用户几何修改伪造新的解剖连接。部分原标注存在左右或骨侧别不一致，目录保留原值并显示问题；这些标签未经独立逐条医学复核。

## 保存和采集接口

ActivityLibraries.getMuscleSnapshot() 返回当前有效配置，schema 为 human-muscle-overrides-v1，包含 sceneId、assetId、assetSha256、revision、referenceOnly，以及 entries。每条 entry 包含 actorId、muscleId、position 三维偏移、scale 三维尺度、bellyScale 肌腹厚度。

全默认结构不占用 entries。位置记录在标准解剖模型父节点局部坐标中，尺度围绕该结构的中心；原始 GLB 不被修改。目录在工作区初始化时读取，所以无需先打开肌肉页，也能检查资产哈希与结构标识。

validateMuscleSnapshot(value) 返回 {ok, reason}，检查版本、场景、资产标识/哈希、人物和结构存在性，以及有限数值和范围。setReplayMuscleSnapshot(saved, {active:true}) 临时显示历史配置；旧记录传 null, {active:true} 时显示无修订的标准体，不采用当前人物的修订。退出传 null, {active:false}，恢复当前实时配置及尚未保存的本地草稿。回放不会改写浏览器存储。

采集或回放时禁止几何修改及保存，仍可选择、筛选、独显和观察。采集 metadata 保存 libraries.muscleOverrides；标准解剖体不附着到总览人物，因此不改变总览动作采样、导航或关键点。用户未开启肌肉页时不会下载大型解剖 GLB。模型加载失败会明确显示错误和重试按钮，不会退回旧示意网格。
