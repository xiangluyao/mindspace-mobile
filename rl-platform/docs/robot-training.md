# 机器人交互与人因示范 · v12.3.2

顶部「训练」在三列实验台中选择 D1（默认）或 IRON、场景和交互训练事件，再进入所选机器人开展专家示范。中央重点显示三维场景与信号波形，采集及信号控制放在侧栏。内容围绕 MindSpace 的空间、人因和行为数据采集，不进行运动学习。原 Human Layer 人类入口保留。

## 使用

1. 运行 `python3 serve.py --no-browser` 并访问实际地址的 `/?view=training`。本机服务当前在5206端口，5205属于较旧副本。
2. 左侧选择型号。默认D1，也可选择原IRON，页面加载真实模型；可下载当前型号的Blender源工程。
3. 默认棋盘场景为16×16米实际地面，使用0.5米蓝绿格，仅有一台所选机器人。在场景下拉中选择餐厅后直接加载既有环境模型，保留16位人物原位并加入所选机器人。页面不再设置「载入场景」按钮。已有自定义场景配置沿用真实资源，不会生成额外建筑。
4. 在左侧「交互事件训练」选择示范情境，再点击「进入机器人 / 专家」。列表按当前机器人动作、场景真实对象与人物排期提供可用事件。训练始终绑定当前选中的D1或IRON；选择事件或观察人物不会切换控制角色，也不会自动开始采集。进入人类角色请使用「Human Layer → 进入角色 / 专家」，可选择所有在场顾客、厨师和服务员，未在场选项禁用。顾客和厨师仅开放移动、转向、接近、等待及让行，不提供E/R点单、递送或端盘操作；服务员保留岗位操作。
5. 填写示范者编号及本机独立采集目录，点击「使用此目录」后开始。两款支持W/S前后、A/D转向、双击地面行走、Enter接近、空格等待；D1的E/R分别为问候/倾听，IRON的E为真实Reach伸手展示、R不触发动作。
6. 餐厅中选择实际人物作为交互对象，人工记录反馈、注意对象、可空舒适度、观察依据与意图假设。标注拒绝后机器人立即停止；对该对象的继续接近会被阻止，直到记录新的人工反馈。棋盘没有人物，观察入口禁用，不生成虚构目标或反馈。
7. 点击「结束并保存」，成功后从「采集回放」打开已保存记录。回放按采集时间显示标注，拖回更早时刻不会提前显示后来的反馈。

左列为型号、场景和交互事件训练，原进入/回放/设备/反馈导航不再占用左侧事件区域。采集和信号控制按钮位于侧栏，中央显示三维场景及脑电/眼动波形。脑电明细位于中央波形右侧，保留「电极质量 / 眼动 / 事件」页签和电极位置头图。训练右栏隐藏重复的「专家示范」「进入当前机器人」和「每次开始独立采集」说明，将新建示范等按钮上移。重复顶部标题及接口说明/导出条已移除。相机仍提供透视/前/侧/顶、实体/骨骼/线框、重置与全屏；相机视窗沿用简洁分隔。上述布局调整针对训练工作区，普通 Human Layer 原布局保留。Neuro默认展开，未连接设备时等待数据，不生成曲线或质量值。示范主题和接近距离应在开始采集前确定。

交互事件包含机器人适用的等待、朝向、让行和已有动作示范，并复用 Human Layer 当前事件库中的真实物体、事件距离规则及人物排期。物体任务使用最近可达路径；人类岗位事件用于观察该情境下的机器人响应，不让机器人代替人物点单、端盘或入座。所需人物或物体不存在时，相应项不可用；有排期不等于事件已发生。选择事件不改原人物排期，动作和采集均由专家确认，不自动评分或训练策略。

## 模型与数据

D1资源位于 `public/assets/d1-social/`，包括可编辑 `.blend`、网页 `.glb`、来源与尺寸清单、真实渲染预览。建模脚本位于 `blender/d1-social/`。模型约0.420米高，13个骨骼，具有Idle/Walk/Greet/Listen。它是参考图原创重建，尺寸、外廓和动画不能作为原厂CAD或标定数据。

IRON继续使用 `public/assets/iron-training/` 的既有模型和源工程，18个骨骼，具有Idle/Walk/Squat/Reach。专家界面提供真实Reach展示动作，不将不存在的Greet/Listen映射成虚构动画；Squat原片段保留在资产中。

角色运动使用所选场景的实际地面导航与碰撞约束，棋盘导航范围为±8米；机器人有单独的碰撞范围。相机锚点和关节来自实际模型。当前没有运动学习、全身刚体动力学、实机控制或学习后的行为策略，机器人不执行人类端盘、点单、入座等动作。

每次示范保存为独立episode，含 `manifest.json`、`frames.jsonl`、`events.jsonl`、`signals.jsonl`。元数据保存 `trainingContext`、模型信息、场景、所扮演角色和人类资料快照。

- 人体关键点在 `frames.keypoints`，机器人实际骨骼世界坐标在 `frames.robotJoints.d1` 或 `frames.robotJoints.iron`。两者目标每0.5秒采样，场景状态目标每0.1秒保存；开始与结束另存完整帧，因此不是每一帧都有关键点或关节坐标。棋盘不产生人体关键点。可选JPEG目标1Hz、最长边640像素；实际频率受渲染与页面可见性影响。
- `social_annotation` 事件保存人工反馈、注意对象、舒适度、观察依据、意图假设及实际几何距离。来源为 `expert-annotation`，设备测量状态为 `not-device-measured`。
- `trainingContext.trainingEvent` 保存选中的交互训练事件、实际目标和来源；引用场景事件时包含其定义及相应人物排期信息。开始采集后记录 `training_event_selected`，回放读取该次采集的事件上下文。
- 每条事件带采集经过时间；场景时间另行保存。设备包来自实际连接，未知数据保持未知。
- 训练记录按场景、`trainingContext.profileId`（`d1-social-v1` / `iron-social-v1`）和所选机器人身份隔离，普通Human Layer仍只列出其适用的采集记录。回放恢复实际相机与动画采样，不显示当前时刻之后的标注或设备包。

原始EEG和眼动只来自实际接收的设备包，不直接变成机器人指令；外部解码候选仍需人工确认。人工人因标注不是设备测量或已训练的心理预测。

页面已移除顶部全局导出条，episode的结束保存和回放继续使用原采集机制。场景状态接口与episode采集分开：棋盘的环境元数据为 `procedural-checkerboard`，没有建筑模型/布局资产，也不带餐厅GLB字段；实际餐厅才保留餐厅资源信息。回放期间禁用实时场景状态导出，避免将当前场景当作历史记录。

## 会话保护

训练iframe与载入的场景iframe持续挂载。切到其他顶部工作区暂停运动，返回保留当前场景与采集身份。采集、结束保存、回放期间锁定型号、场景和交互训练事件。保存失败保留锁定状态，可重试结束保存。刷新仍会重建浏览器页面，完成示范后应先保存。私人采集目录、设备凭据和另一端口的浏览器配置不会自动迁移。

## 开发

训练外壳为 `training.html` 与 `src/training-workspace.js/css`，场景内三列适配与侧栏控制为 `src/robot-training-layout.js/css`，交互训练事件由 `src/robot-training-events.js` 读取现有定义、对象和排期。`src/robot-training-profile.js`、`src/d1-scene-profile.js` 配置两款机器人、可用动作和棋盘；`src/main.js` 加载实际环境。训练标注与控制为 `src/social-training-integration.js`、`src/social-training-domain.js` 和 `src/expert-controller.js`；`src/d1-workspace-session.js` 沿用历史文件名，服务两款机器人的会话。

内部场景示例为 `human-layer.html?section=expert&training=d1&sceneId=training-checkerboard&trainingShell=1` 或 `human-layer.html?section=expert&training=iron&sceneId=restaurant&trainingShell=1`。训练未指定 `sceneId` 时默认棋盘；无 `training` 参数保持原Human Layer。棋盘仅注入训练目录，不改原人类场景目录。`src/d1-preview.js` 和旧运动学习模块为历史代码，不是当前训练入口；IRON模型仍实际使用。

修改后运行 `npm ci`、`npm test`、`NO_PROXY='*' no_proxy='*' python3 -B -m unittest discover -s tests -p storage_capture_test.py`、`npm run build`。旧迁移快照校验不适用于更新后的带哈希构建文件，不要覆盖原迁移记录。
