# MindSpace Human Layer v9

可交互的本地三维餐厅仿真。沿用 MindSpace 界面与 8 月 25 日 13:49 餐厅模型，包含10位顾客、3位厨师和3位服务人员。本轮更新场景选择、人物属性层级、动作显示与姿态编辑、事件物体类别多选，并移除重复导航。

## 启动

完整解压后，macOS双击 `启动仿真.command`，Windows双击 `WINDOWS_START.bat`；需要 Python 3。也可运行 `python3 serve.py`，打开打印的本地地址。使用已经构建的网页不需要 Blender 或 Node.js。

主平台顶部 **Human Layer ▾** 是五个页面的统一入口。旧的整行重复导航已删除；直接打开 `human-layer.html` 时，在页面标题处提供页面切换。

| 入口 | 内容 |
| --- | --- |
| 总览窗口 | 人物选择、六层逻辑、L3个人事件时间序列、显式框选组队 |
| 人格库 | 先选人物，基础属性、大五人格、行为标签三个同级页签 |
| 动作库 | 岗位动画、实体/骨骼/关键节点/肌肉示意、姿态修订 |
| 事件库 | 多选交互物体类别，设置距离、时长、动作与最近可达路径 |
| 进入角色 / 专家 | 铺满视窗、固定双向视野、平面轨迹、示范采集及回放 |

## 场景选择

五个页面的现有标题区域均有“场景选择”。当前提供“餐厅 · 展示场景”；“＋”可以用当前模型建立独立的场景配置。新配置共用模型资源，人物属性、事件、团队、视野、姿态修订各自保存，不复制当前场景已修改的数据。配置名称用于区分实验；新建配置不会生成另一个建筑模型。

场景切换会重新初始化所选场景并保留当前页面；同一场景内部换页不重建三维渲染器。采集、回放、结束保存期间禁止切场景。原餐厅浏览器数据按需兼容读取，之后写入场景命名空间，原键保持不变。

未来场景通过 `public/data/human-scenes.json` 的目录配置、资产清单和场景存储包装器接入。`window.mindspaceHumanLayer.getSceneContext()` 返回当前上下文，`registerScene(definition)` 可注册有效的同站资源配置。不同建筑的地板、导航、座位、人物和事件语义仍需各自提供并适配，当前实际完成的建筑模型只有餐厅。详见 [场景接口](docs/scene-context.md)。

## 人格库

全部16人作为独立入口；无需先选择人格模板。**基础属性、大五人格、行为标签**同级，每个区域单独保存，切换页签保留未保存草稿。

基础属性包含年龄、性别、身高、可选体重；未知值保持空白，不从外观推断。基础身高仅存资料，不缩放模型。大五OCEAN五维可选配置，默认未启用；后续可补外部来源，不代表已实测人格。行为标签、消费关注和表达偏好与前两者平行。

旧模板只保留为可选辅助工具。编辑绑定了共享模板的某个人时，自动为此人建立独立档案，不影响别人。支持当前场景JSON导入导出；采集/回放期间只读。点评语言结果、店铺点评界面已移除。详见 [人物资料说明](docs/persona-library.md)。

## 动作显示与编辑

动作库按顾客、厨师、服务员限制可用动作，共192条Blender骨骼动画。显示模式包括：

- **实体**：原有人物表面与服装。
- **骨骼**：显示骨骼关节，可选中并修改位置。
- **关键节点**：显示27个标记及连接，可调整标记相对所属骨骼的局部偏移。
- **肌肉示意**：Blender制作的示意资源随骨骼运动；不是原模型真实肌肉，也不是解剖或肌肉动力学仿真。

点击三维节点或从右侧选择节点会暂停预览；可拖动彩色坐标轴，或填写X/Y/Z偏移。支持撤销、重做、恢复原始、保存当前人物/动作、导出偏移JSON。骨骼位置编辑影响人体变形；关键点编辑只修正标记位置，不拉动人体网格。

修订按**场景＋人物＋实际动画片段**独立保存。点击保存后，同步总览中相同人物和动作；应用动作时会先保存有效草稿。骨骼偏移是动画采样后的局部叠加；导航根节点锁定，不用于移动人物或避墙。每轴骨骼限0.08米、手指限0.025米、关键点限0.10米。范围限制不等于自动解剖校验或全身IK约束。

原始人物GLB不被修改。肌肉示意Blender源工程在 `public/assets/pose-v9/`；构建源脚本在 `blender/v9-pose-tools/`。已有的坐姿仍使用餐厅原椅子，不创建新凳子。动作来源及岗位动画见 [v8动作说明](docs/expanded-actions-v8.md)。

## 事件与顾客活动

事件库只定义规则：**交互物体类别使用复选框，可多选**，不再提供具体可交互物体列表。执行时合并所选类别的实际可用目标，按可达路径总长选最近目标，检查距离阈值。动作与类别必须匹配；没有有效目标时等待或报告原因，不穿墙、不伪造目标。

为人物安排执行时刻，请到 **总览 → 选择人物 → L3社会情境建模**。每人独立时间序列，前一事件未结束时后续事件等待。手动控制优先，采集/回放期间不改计划。物体页面仍负责“物体是什么”，本页负责怎样使用、何时可用。

初始3人候位、1人找座、2人看菜单、1人请求点单、1人用餐，另2人在65/95秒尝试进店。顾客按规则经历候位、找座、点单、等餐、用餐、结账、离店；拥堵时等待、重规划或失败，不保证所有排期必然完成。工作人员保持岗位动作和区域限制，交互机器人由工作人员替代。原有前厅与后厨地板、墙体和座位约束继续使用。

每个人仍是独立agent，可在总览显式框选几个人，设置朋友/家人等关系及聚餐等场合。组队不自动移动人物或强制统一行为。高层算法仍可通过 `setBehaviorAdapter(fn)` 接入，目前为规则仿真。

## 专家视野、采集与回放

进入专家页后，仅保留右侧必要工具。水平与垂直视野均使用滑块，数字只读，水平预设按钮已删除。默认90°×60°，两项独立按场景/人物保存；窗口大小变化不改变角宽。转头/抬头调整的是观察方向，放在独立折叠项中。右上平面图展示实际位置和轨迹。

每次进入服务员角色前，填写示范者编号，选择p14–p16及真实可写保存位置。开始后创建独立episode；WASD移动/转向，双击地面寻路，Enter接近，E回应，R递送。结束并保存后可回放。

文件包括 `manifest.json`、`frames.jsonl`、`events.jsonl`、`signals.jsonl`。状态目标10Hz、完整432关键点目标2Hz、JPEG目标1Hz，实际受渲染速度限制。元数据包含场景上下文、人物属性、姿态修订、团队、计划和初始视野；每帧保存实际相机与动画采样状态。回放临时使用历史修订和采样，退出恢复当前设置。旧记录没有动画混合权重，只能确定性重建，过渡段不能声称逐帧完全一致。回放列表按场景隔离；无场景上下文的旧餐厅记录继续兼容。

脑电和眼动仅记录本机设备桥真实收到的数据。未连接设备时信号数为0。当前没有内置EEG解码器、真实心理状态测量、训练后行为策略或机器人部署。详见 [采集接口](docs/capture-api.md)、[视野说明](docs/camera-view.md)。

## 工程与验证

源码修改后运行 `npm install`、`npm test`、`npm run build`。启动器服务 `dist`；开发页面为5206，需另启采集后端。四视图建模的 `perspective.html` 沿用原交互餐厅资产。

本轮真实验收与证据见 [VALIDATION.md](VALIDATION.md) 和 `examples/human-layer-v9-validation/`。历史版本文档与证据保留，不能当作本轮新测结果。资产来源见 [SCENE_ATTRIBUTION.md](SCENE_ATTRIBUTION.md)、[ASSET_LICENSES.md](ASSET_LICENSES.md)。交付不包含开发缓存、原始测试采集或受限词典。
